## What the suite is

14 files under `src/test/`, **192 tests**, run with `vitest run`. `fileParallelism` is off:
race-condition tests need a file to own the database, and every `beforeEach` truncates
~30 tables.

The tests talk to a **real Postgres**, not a mock. Most of what they assert lives in the
schema itself — partial unique indexes, FK cascades, lock behaviour — so a mock would
verify nothing.

## Running it locally

`src/lib/db/index.ts` picks the driver from the URL: a `localhost` / `127.0.0.1` host gets
the plain `pg` driver, anything else gets Neon's WebSocket driver. So a local Postgres
needs no application change.

```
initdb -D <dir> -U postgres --auth=trust
pg_ctl -D <dir> -o '-p 5433 -k /tmp' start
createdb -h /tmp -p 5433 -U postgres tecxwork_test

DATABASE_URL=postgresql://postgres@localhost:5433/tecxwork_test npx drizzle-kit push --force
TEST_DATABASE_URL=postgresql://postgres@localhost:5433/tecxwork_test \
DATABASE_URL=postgresql://placeholder:placeholder@127.0.0.1:1/unused \
  npm test
```

`drizzle/` is gitignored — `schema.ts` is the source of truth, so the test database is
built by **pushing the schema**, not by replaying migrations.

`src/test/setup.ts` refuses to run when `TEST_DATABASE_URL === DATABASE_URL`, so a
misconfigured run cannot truncate a real database. The placeholder `DATABASE_URL` above
exists only to satisfy that guard.

## Local Postgres removed the flake

The suite previously ran against a shared Neon branch at 0.25 CU over a WebSocket pool,
and across ~180 tests that socket would occasionally drop — surfacing as a failed
`set lock_timeout` in `beforeEach` on an otherwise healthy test. `withReconnect` was added
to retry once and distinguish "the connection blinked" from "the query is wrong."

Measured 2026-08-11 against local Postgres 16: **192/192, twice, no reconnects fired.**
The mitigation stays (it still protects a Neon-targeted run), but the local path is the
cure the earlier note was waiting on.

## Gotcha: typecheck before build reports phantom errors

`next-env.d.ts` is gitignored and generated by `next build`. On a clean checkout,
`tsc --noEmit` reports ~25 errors of the form `Cannot find module 'next/server'` /
`Could not find a declaration file for module 'next/link'`. **These are not real.** Build
first, then typecheck — which is the order CI uses.

## CI

`.github/workflows/ci.yml` — runs on pushes to `main` and `demo/yang-luck`, and on every
pull request. A `postgres:16` service container backs the test step.

Order matters: `npm ci` → **lint** → `drizzle-kit push` → **build** → **typecheck** →
**test**. Build precedes typecheck for the `next-env.d.ts` reason above.

Note `next build` does **not** run ESLint, so a lint error is invisible to a build-only
check — which is how `react-hooks/set-state-in-effect` sat unnoticed in
`src/app/pipeline/pipeline-board.tsx` until the first lint run in this repo's history.
Lint runs first in CI for exactly that reason.
