Technical Handoff & PRD: University Recruitment Booking System

1. Executive Summary

This document outlines the architecture, deployment strategy, and configuration for a single-day, high-concurrency recruitment booking platform.

The Constraint: The system will experience an immediate traffic spike (approx. 1,000 concurrent users) when the event opens.
The Solution: Instead of building custom booking logic or self-hosting complex server infrastructure, we have built a custom recruitment platform using Next.js, Neon Postgres, and Resend. This platform handles authentication, directory listing, slot management, and automated notifications in a unified experience. File storage (CVs/JDs) is completely offloaded to Google Drive to ensure strict data privacy.

2. System Architecture & Tech Stack

2.1 Core Engineering Stack

Provider: Vercel (Frontend & API), Neon (Serverless Postgres).

Auth: Custom JWT + bcrypt system.

Slot Logic: Atomic slot reservation system implemented in Next.js API routes with Drizzle ORM.

Email Infrastructure: Handled by Resend API (custom templates for student and recruiter notifications).

Timezone: Strictly Asia/Taipei (UTC+8) configuration in the database and date-handling logic.

2.2 Frontend Architecture: The Directory

The platform integrates a dynamic directory and booking system into a single Next.js App Router application.

Stack: Next.js, Tailwind CSS, Shadcn UI.

Hosting: Vercel.

Functionality: A real-time grid of recruiters with live status (available/busy) and direct booking modals.

Routing: Internal Next.js routing (e.g., /recruiter/[id]).

3. Configuration & Data Privacy Protocol

To comply with Taiwan's Personal Data Protection Act (PDPA/PIPA) and prevent unauthorized access to CVs, the system utilizes "Explicit Targeted Sharing" via Google Drive.

3.1 Recruiter Setup (Data In)

Admin creates recruiter accounts and job listings in the internal dashboard.

Recruiters log in with their corporate email to set their profile and JD links.

Recruiters set their event day availability (integrated in the recruiter dashboard).

Job Description (JD) & Authorized Email (CRITICAL): The recruiter pastes the Google Drive link to their JD directly into their profile description. Crucially, the recruiter MUST clearly state their official corporate email address in this description (e.g., "Please grant CV file access to: hr@company.com").

3.2 Jobseeker Flow (Data Out)

User clicks the recruiter from the Directory.

User selects an available time slot from the custom slot picker.

The Secure CV Link (PIPA Compliance): The platform enforces a required CV field:

Label: "Link to your CV (Google Drive)"

Type: URL / Text

Helper Text: "IMPORTANT: Do NOT set your link to 'Anyone can view'. For your privacy, you must explicitly share your Google Drive file ONLY with the recruiter's official email address listed in their description."

PIPA Compliance Checkbox: Add a required boolean (checkbox) custom field:

Label: "I consent to the collection of my CV link for this recruitment event in accordance with Taiwan's Personal Data Protection Act. I confirm I have only granted Drive access to the specified recruiter."

4. Load Testing & QA Protocol

Load Testing is performed against the Next.js API endpoints on Vercel and the Neon Postgres database.

Target of QA: The Booking API (/api/bookings) and Slot Discovery API (/api/slots).

Tooling: Use k6 to hit the Vercel-hosted API with 1,000 concurrent Virtual Users (VUs).

Internal Logic Test: Atomic database updates are verified to handle simultaneous "Confirm" clicks, ensuring that the same slot cannot be booked by two users (race-condition handling).

7. Contingency Plan (Disaster Recovery)

If the primary platform (Vercel/Neon) experiences critical downtime, a low-tech fallback is ready.

7.1 The Fallback Mechanism

Tool: Google Forms with Emergency Slot management.

All recruiter URLs are batch-replaced with the Emergency Form link via a manual environment variable "EMERGENCY_MODE" in the Next.js app.

Students fill the form, and data is manually distributed post-event.
