Technical Handoff & PRD: University Recruitment Booking System

1. Executive Summary

This document outlines the architecture, deployment strategy, and configuration for a single-day, high-concurrency recruitment booking platform.

The Constraint: The system will experience an immediate traffic spike (approx. 1,000 concurrent users) when the event opens.
The Solution: Instead of building a custom booking engine, we are deploying a custom-built scheduling engine powered by Next.js and Neon Postgres to handle the scheduling logic. File storage (CVs/JDs) is completely offloaded to Google Drive to save bandwidth and storage costs, utilizing strict permission controls to ensure data privacy.

2. System Architecture & Tech Stack

2.1 Core Infrastructure (Cloud VM / VPS)

Provider: DigitalOcean, AWS (EC2), or Google Cloud (Compute Engine).

App Server Specs (Minimum): 4 vCPU, 8 GB RAM (Serverless scaling via Neon and Vercel reduces the need for large fixed VM specs).

Deployment Method: Vercel (Frontend/API) + Neon (Serverless Postgres).

Timezone: Must be strictly configured to Asia/Taipei (UTC+8) across the OS, Database, and App configurations to avoid scheduling drift.

2.2 Network & Edge Caching

Proxy/WAF: Cloudflare.

Requirement: Strict Page Rules must be configured to cache all static assets aggressively. Only /api/ routes and dynamic SSR pages should hit the origin server.

SSL: Let's Encrypt (Automated via Traefik or Nginx proxy in Docker).

2.3 Database & State

Primary DB: Neon Serverless PostgreSQL (utilizing Drizzle ORM).

Connection Pooling (CRITICAL): Neon's built-in connection pooling handles concurrent Node.js clients efficiently.

Cache/Queue: Lucide-react for iconography and Resend for transactional emails. (Redis not strictly required for this custom implementation).

2.4 Third-Party Integrations

Authentication: Custom JWT + bcrypt implementation (self-contained).

Transactional Email: Resend (Modern developer-first email API).

Warning: Do not use a standard SMTP server. You must authenticate the sending domain (e.g., @event.university.edu.tw) with SPF, DKIM, and DMARC to ensure booking confirmations bypass spam filters.

3. Frontend Architecture: The Directory

Cal.com was previously considered but the platform now uses a custom integrated directory and booking flow built directly into the Next.js app.

Stack: Next.js (App Router), Tailwind CSS, Shadcn UI. Hosted on Vercel.

Functionality: A unified dashboard for students to browse and book interviews directly.

Routing: Clicking a company opens the internal booking modal/page (e.g., /recruiter/[id]).

4. Data Privacy & PIPA Compliance

To comply with Taiwan's Personal Data Protection Act (PDPA/PIPA) and prevent unauthorized access to CVs, the system utilizes "Explicit Targeted Sharing" via Google Drive.

4.1 Recruiter Setup (Data In)

Admin creates recruiter accounts via the internal Admin Dashboard.

Recruiter sets their event day availability and profile details.

Job Description (JD) & Authorized Email (CRITICAL): Recruiter pastes the Google Drive link to their JD directly into their profile. Crucially, the recruiter MUST clearly state their official corporate email address in this description (e.g., "Please grant CV file access to: hr@company.com").

4.2 Jobseeker Flow (Data Out)

User clicks recruiter from the Directory.

User selects an available time slot from the custom slot picker.

The Secure CV Link (CRITICAL CONFIG): The system enforces a required CV field during sign-up or booking:

Label: "Link to your CV (Google Drive)"

Type: URL / Text

Helper Text: "IMPORTANT: Do NOT set your link to 'Anyone can view'. For your privacy, you must explicitly share your Google Drive file ONLY with the recruiter's official email address listed in their description."

PIPA Compliance Checkbox: Add a required boolean (checkbox) custom field:

Label: "I consent to the collection of my CV link for this recruitment event in accordance with Taiwan's Personal Data Protection Act. I confirm I have only granted Drive access to the specified recruiter."

5. Load Testing & QA Protocol

The system MUST be tested for the "9:00 AM Thundering Herd" problem.

Tooling: Use k6 (Grafana) or Locust.

Target Metrics:

Simulate 1,000 Virtual Users (VUs) ramping up over 60 seconds.

Target endpoint: The internal booking API (/api/bookings/mine) and slot availability API (/api/slots).

Acceptable Error Rate: < 0.1%.

Acceptable p95 Response Time: < 800ms.

Monitoring: Monitor htop (CPU usage) and PostgreSQL active connections during the test. If CPU hits 95%+, scale the VM to 16 vCPU.

6. Execution & Deployment Timeline

T-Minus 14 Days (Infrastructure):

Provision Neon Project and Vercel Project.

Set up Custom Domain and SSL.

Verify Resend sender domain.

T-Minus 10 Days (Configuration & Testing):

Configure Event Modes and PIPA consent logic.

Deploy Next.js application to Vercel.

T-Minus 7 Days (Load Test):

Execute k6 load test. Tune PgBouncer limits based on results.

T-Minus 3 Days (Data Entry):

Recruiters onboard, generate links, paste JD links, and list their authorized receiving emails.

Event Day:

DevOps on standby monitoring Cloudflare analytics and server CPU.

Export PostgreSQL database from Neon (for university records/metrics).

Purge all personal data (CV links/emails) from the database to ensure strict privacy compliance.

7. Cost Estimation (Fact-Checked for 2026)

This model leverages open-source software and existing university infrastructure to keep software licensing costs at $0, shifting the budget entirely to temporary cloud compute and labor.

Cloud Infrastructure (Vercel + Neon): $0 - $19 USD

Neon Free tier and Vercel Free tier are sufficient for the expected load, but a small upgrade to the "Launch" plan may be used for peace of mind.

Transactional Email (Resend): $0

Resend free tier allows 3,000 emails/month, which covers the event comfortably.

Edge Caching & DNS (Cloudflare): $0

The Free Tier strictly handles the required static caching and DDoS protection.

Storage (Google Drive): $0

Jobseekers and Recruiters utilize their own personal or workspace Google Drive quotas.

Domain Registration: $0

Assumes the use of an existing university subdomain (e.g., recruit.university.edu.tw).

Total Software & Infrastructure: ~$97.00 USD (Approx. $3,100 NTD)
