  Bottom Line

  For TecxMeet's use case (1-day event, ~50 recruiters, ~1,000 students), the public endpoints are more than sufficient. The main work is:

  1. Set up recruiter accounts + event types in Cal.com UI (:3001)
  2. Store their eventTypeIds in TecxMeet's recruiter data
  3. Configure the CV link + PIPA custom fields once per event type

  How it works now

  Student clicks "View & Book" on recruiter card
    → /recruiter/[id] loads with slot picker
    → GET /api/cal/slots → Cal.com /api/trpc/public/slots.getSchedule
    → Student picks a time, fills form (name, email, CV link, PIPA consent)
    → GET /api/cal/event-type → resolves eventTypeId (cached after first call)
    → POST /api/cal/bookings → Cal.com /api/book/event
    → Success confirmation shown

  Three public endpoints used, zero API keys needed:

  Setup steps (one-time):                                                                                                                                                          
                                                                                                                                                                                   
  1. Start Cal.com: docker compose up -d (already running)                                                                                                                         
  2. Create an admin account at http://localhost:3001/auth/setup                                                                                                                   
  3. Create a test recruiter user in Cal.com with username matching one in data.ts (e.g. tecxmeet-tsmc)
  4. Create a "15min-interview" event type for that user with availability set                                                                                                     
  5. Start TecxMeet: cd app && npm run dev                        
  6. Test: Go to http://localhost:3000 → click TSMC → pick a slot → book
